# 主题配置工具 - 视差壁纸功能扩展需求文档

## 1. 背景与目标
当前主题配置工具仅支持单张“静态壁纸”。为了提升主题的视觉表现力，需扩展支持“视差壁纸”功能。视差壁纸由多张带有透明通道的图片层叠组成，通过设备重力感应或滑动产生视差效果。
本需求旨在明确视差壁纸的**导入、预览、合成逻辑及导出规范**。

---

## 2. 详细功能需求

### 2.1 界面交互优化 (UI/UX)

#### 2.1.1 编辑区操作入口
*   **位置**：右侧编辑区域（现有“导入壁纸”按钮旁或壁纸设置栏内）。
*   **新增元素**：增加 **“导入视差壁纸”** 按钮。
*   **交互行为**：
    *   点击按钮后，弹出系统文件选择框。
    *   **支持多选**：允许用户同时选择多张图片文件。
    *   **支持文件夹选择**：允许用户直接选择一个文件夹，程序自动扫描该文件夹下的符合规则的文件。

#### 2.1.2 文件校验与过滤规则
导入时需对文件进行严格过滤，仅加载符合以下规则的图片：
1.  **文件后缀**：必须为 `.png`（支持透明通道）。
2.  **文件前缀**：文件名必须以 `wallpaper` 开头。
3.  **命名示例**：`wallpaper_1.png`, `wallpaper_bg.png`, `wallpaper_layer_2.png` 等。
4.  **排序逻辑**：系统需解析文件名，按照**文件名中的数字/字母顺序**（Ascending Order）进行升序排列。排序靠前的文件作为**底层（背景）**，排序靠后的文件作为**顶层（前景）**。

### 2.2 预览逻辑

#### 2.2.1 壁纸列表缩略图 (右侧编辑区)
*   **静态壁纸**：逻辑保持不变（显示单张缩略图）。
*   **视差壁纸**：
    *   **显示方式**：程序需在内存中将导入的多张切片图，按排序顺序进行叠加合成。
    *   **合成算法**：`Layer 1 (Bottom) + Layer 2 + ... + Layer N (Top)`。
    *   **展示**：将合成后的图像生成一张缩略图展示在列表中。

#### 2.2.2 主预览界面 (左侧预览区)
*   **静态壁纸**：逻辑保持不变。
*   **视差壁纸**：
    *   **实时合成**：在左侧模拟手机/设备界面的预览区，按层级顺序渲染所有图层。
    *   **视觉效果**：确保透明通道正确渲染，避免黑底或白底干扰，还原该组图在真机上的层叠效果。

### 2.3 导出逻辑 (Export)

在导出主题包（Zip）或保存配置时，系统需根据当前壁纸类型（静态 vs 视差）执行不同的打包策略。

#### 2.3.1 场景 A：静态壁纸 (保持现有逻辑)
*   **文件名处理**：将用户导入的图片重命名为 `wallpaper.jpg` (或保持原格式，根据旧逻辑)。
*   **Zip 包结构**：
    ```text
    theme_pack.zip
    ├── icon_color_adapter.json
    └── wallpaper.jpg
    ```

#### 2.3.2 场景 B：视差壁纸 (新增逻辑)
*   **文件名处理**：**严禁修改文件名**。直接保留导入时的原始文件名（如 `wallpaper_01.png`），以确保主题引擎能通过文件名识别层级顺序。
*   **Zip 包结构**：
    ```text
    theme_pack.zip
    ├── icon_color_adapter.json
    ├── wallpaper_1_sky.png      <-- 层级1
    ├── wallpaper_2_mountain.png <-- 层级2
    └── wallpaper_3_trees.png    <-- 层级3
    ...
    ```

## 3. 逻辑流程图 (伪代码描述)

```text
[用户点击导入视差壁纸]
      ↓
[选择文件/文件夹]
      ↓
[系统过滤]
   ├─ 检查后缀是否为 .png?
   └─ 检查前缀是否以 "wallpaper" 开头?
      ↓
[排序处理]
   └─ 按文件名自然顺序排序 (Layer_1 -> Layer_2 -> Layer_N)
      ↓
[更新数据模型]
   ├─ 设置壁纸模式 = "Parallax"
   └─ 存储文件路径列表 = [path1, path2, path3...]
      ↓
[界面刷新]
   ├─ 左侧预览：按顺序叠加渲染所有图层
   └─ 右侧缩略图：生成叠加后的静态缩略图
      ↓
[用户点击导出 Zip]
      ↓
[判断壁纸模式]
   ├─ 模式 == Static:
   │    └─ 写入 icon_color_adapter.json
   │    └─ 写入 wallpaper.jpg (重命名)
   │
   └─ 模式 == Parallax:
        └─ 写入 icon_color_adapter.json
        └─ 遍历路径列表:
             └─ 写入文件 (保持原文件名，如 wallpaper.._1...png)
```

## 4. 异常与边界情况处理

1.  **尺寸不一致**：
    *   如果导入的多张视差图片尺寸（分辨率）不一致，预览时以**第一张图（最底层）**的尺寸为基准，后续图层进行拉伸或居中适应（开发需确认具体对齐策略，建议要求用户导入同尺寸图片）。
2.  **文件缺失**：
    *   如果导入文件夹中没有符合 `wallpaper*.png` 规则的文件，需弹出提示“未找到有效的视差壁纸文件”。
3.  **模式切换**：
    *   当用户已经导入了视差壁纸，又点击了“导入静态壁纸”，系统应清空当前的视差壁纸列表，切换回静态模式，反之亦然。

## 5. 开发验收标准 (Checklist)

*   [ ] 点击“导入视差壁纸”能正确筛选 `.png` 且以 `wallpaper` 开头的文件。
*   [ ] 导入乱序文件（如 `_2.png`, `_1.png`）后，预览界面能自动纠正为 `_1` 在下，`_2` 在上。
*   [ ] 左侧预览区和右侧缩略图能正确显示叠加后的透明效果，无错误背景色。
*   [ ] 导出 Zip 包时，解压后检查：包含 `icon_color_adapter.json` 且包含多个未改名的 png 壁纸文件。
*   [ ] 导出静态壁纸时，Zip 包结构未受影响。
